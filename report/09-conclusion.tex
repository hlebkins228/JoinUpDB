\chapter*{ЗАКЛЮЧЕНИЕ}
\addcontentsline{toc}{chapter}{ЗАКЛЮЧЕНИЕ}

В работе проанализированы предметная область и известные решения, определены требования к системе. Построена модель данных, спроектированы таблицы и связи, рассмотрены ограничения целостности и соответствие третьей нормальной форме.

Разработаны база данных PostgreSQL и приложение JoinUp для поиска и организации мероприятий. В БД настроены роли и права доступа, индекс поиска и триггер, который записывает факт перехода мероприятия в состояние удаленного. Проверены отдельные запросы приложения, права ролей БД и переходы признака удаления. Сценарии записи через HTTP в проведенную проверку не входили.

По пяти критериям сравнения JoinUp отвечает четырем, а Timepad -- пяти: в JoinUp не предусмотрена запись без учетной записи. Для учебной задачи реализованы поиск, публикация и участие в мероприятиях.

Исследование основного запроса поиска показало уменьшение среднего времени выполнения при наличии индекса для четырех объемов данных от 1000 до 10000~мероприятий. При 10000~мероприятий получены 4,905~мс без индекса и 3,038~мс с ним. Полученный результат относится к условиям проведенного исследования.

Результаты могут использоваться в учебных проектах с реляционной БД. Дальнейшая работа -- проверка сценариев записи через интерфейс.
